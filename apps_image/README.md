# apps_image

This folder holds the welcome app, the one app a Kode Dot leaves the factory with: `kodediy/kode-app-onboarding`, a private repository of Kode, the folder `apps/bienvenida`, project `onboarding`. `sdkconfig.defaults` names it in `CONFIG_KODEOS_WELCOME_APP`.

`welcome.pin` is the one file here in git: one line, `<repository> <app folder> <commit>`. `tools/build_welcome.sh` clones that repository into `build_welcome/src`, builds the folder at that commit and writes two files here: `<project>.kfw`, the app packed with the `appdata/` folder it carries (its `app.json` and icon), and its stamp `<project>.commit` ("<commit> <sha256>", `-dirty` on local changes). It also writes that app data into `storage_image/.kode/appsdata/<project>/`, so run it before `idf.py build`: the build makes the FAT image. Moving the pin is a deliberate change, like moving the C5's.

The kfw is the one copy of the welcome app, and three things come out of it. `tools/assemble_release.sh` builds the factory pack's `apps.bin` from it with `tools/mkapps.py`: the apps region's directory with the app installed in it, the image at the first page of data, and no boot request. The FAT image carries its `app.json` and `icon.k64` in the app's data folder, where an install on the board would have left them and where Apps reads the app's icon, colour and description. And the release publishes the kfw itself as `<project>-v<version>.kfw`, to install the app again on a board that lost it (`python3 tools/kcli.py -p PORT install <project>-v<version>.kfw --dst app`). `flash.sh` writes it at the region's base. kodeOS boots on it and lists the app in Apps. The factory reset that the final station runs on a PASS keeps the app and writes its boot request right before ship mode, so the customer's first power-on runs it.

The release refuses a kfw that is missing, has no stamp, was built from another commit than the pin, is not the stamped one, or carries another project name than `CONFIG_KODEOS_WELCOME_APP`. It also refuses a FAT image whose data folder for the app is missing or is not the kfw's own.

**The kfw and its stamp are not in git.** `.gitignore` excludes `*.kfw`, `*.bin` and `*.commit` in this folder. A release runs `tools/build_welcome.sh`, which clones the pinned commit over SSH, so it needs a key that reads kode-app-onboarding: only Kode's does. A fork points `welcome.pin` at a welcome app of its own.
